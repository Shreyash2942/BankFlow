# ADR-004: exact and traceable banking domain model

Date: 2026-09-27. Status: accepted for local development.

Day 3 converts the PostgreSQL schema created in revision `0001` into the transactional source of truth required by the PRD. The model must support later repositories, authentication, atomic balance changes, event publication, and analytics without inheriting the academic prototype's floating-point defects.

## Decisions

- Use UUID primary keys generated by the application for customers, accounts, cards, transactions, and audit events.
- Store all monetary values as `NUMERIC(18,2)` and Python `Decimal`. Reject negative account balances and balance snapshots at the database boundary.
- Represent statuses/types with Python `StrEnum` and named non-native SQLAlchemy enums. PostgreSQL stores readable VARCHAR values and named CHECK constraints, avoiding separate PostgreSQL enum-type lifecycle migrations.
- Store timezone-aware created/updated timestamps. Add an integer ORM version counter to accounts for later lost-update detection; Day 6 will still define locking and transaction-service behavior.
- Retain financial history with `RESTRICT` foreign keys. Audit-event references use `SET NULL`, allowing the append-oriented audit record to survive removal of a referenced demo entity.
- Persist a fictional card token and last four digits rather than a payment-card PAN. Persist only an encoded, salted PIN hash. Failed-attempt counters remain temporary Redis state; permanent card status remains PostgreSQL state.
- Keep audit event types as strings and details as JSONB because the event vocabulary will expand with authentication, transaction, Kafka, and analytics milestones. Services must prevent secrets from entering details.
- Seed fixed fictional UUIDs and business identifiers idempotently. If only part of that fixed graph exists, stop without mutation so inconsistent local data is visible.

## Consequences

Revision `0002` creates five operational tables and can reverse cleanly in the isolated test database. The application database contains one fictional demo graph with a $500.00 starting balance. Repository and service layers must use these relationships and constraints instead of duplicating schema logic.

The seed contains a private scrypt encoder solely to avoid ever inserting plaintext. Day 5 must move hash creation/verification into the authentication utility and retain support for this encoded format.
